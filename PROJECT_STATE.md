# Project State: SecureVision
* **Current Phase:** P12-P13 PostgreSQL migration verification (2026-11-12); proposal parity is gated on the database-contract risks below.
* **Status:** P5 evaluation remains a negative result. ML-assisted likelihood and risk are nullable experimental advisory fields; the deterministic 320-rule tier remains primary and unchanged.
* **Data Split:** Train: 2022-2024, Val: 2025, Test: 2026-01 to 2026-09-08 (Held-Out). Prospective Holdout running daily.
* **Label Definition:** in_cisa_kev_catalog AND (kev_date_added <= published_date + 30 days).
* **Likelihood Provider:** Deterministic scoring remains unchanged. Frozen calibrated XGBoost is an additional advisory signal using publication-time CVSS/vector/CWE/description features only; KEV and EPSS are excluded from model features.
* **ML Risk Formula:** `likelihood × exposure_factor × criticality_factor`; constants, validation-derived risk thresholds, and recommended-action templates are in `backend/rules_config.py`.
* **Model Results:** Authenticated `/model/results` and frontend Model Results screen expose only recorded evaluation data, with unavailable metrics left null/not available.
* **Database:** PostgreSQL 16 is the application database. `DATABASE_URL` is required and is used by SQLAlchemy and Alembic. Pinned driver: `psycopg2-binary==2.9.9`.
* **Schema migration:** Alembic owns the schema, including asset metadata/review fields, ML score-history columns, the CVE cache, audit rows, findings indexes, and PostgreSQL audit immutability triggers. Revision `0002_audit_truncate` also blocks TRUNCATE. Startup runs `alembic upgrade head`; application imports do not create tables or issue raw ALTER statements. ORM audit guards remain.
* **Authentication:** `/me` is available; login throttling allows five failed attempts per username/IP in 15 minutes and is process-local. Refresh tokens were deferred; PBKDF2-HMAC-SHA256 remains at 600,000 iterations.
* **Assets:** Admin/analyst create, edit, and delete are audited transactionally; assets with findings cannot be deleted. CSV host/IP lookup checks both asset name and `ip_or_domain`.
* **CVE lookup:** The prepared `data/processed/master_cves_2026-10-08.csv` is read-only and lazy when present, but is ignored by Git and omitted from Docker. Fresh clones and the image use the PostgreSQL cache and external NVD/FIRST providers; uncached lookup is therefore not guaranteed offline. Three `DEMO_CACHE` values are illustrative fixtures, not authoritative live scores.
* **Deployment:** Compose uses PostgreSQL 16 and a named volume with credentials supplied by environment. No database host port is published by default; `docker-compose.local.yml` adds a loopback-only port for local development. Backend startup waits for PostgreSQL health and migrates before serving.
* **Synthetic demo:** Compose explicitly enables `SECUREVISION_DEMO_MODE`; the demo seeder uses the same configured `DATABASE_URL` as the app and never clears existing rows. The UI shows a synthetic-data badge in demo mode. Seeded ML predictions are intentionally unavailable without NVD enrichment.
* **SQLite conversion:** `scripts/sqlite_to_postgres.py` is manual-only and source-read-only. It was exercised only with a newly created synthetic source and isolated PostgreSQL targets; it preserved IDs/timestamps, copied score history/audit rows, filled legacy asset metadata, reset sequences, verified counts, and refused a nonempty rerun. It is never called by routine startup.
* **Testing strategy:** Default `pytest` uses isolated temporary SQLite fixtures. The Compose `postgres-tests` profile runs the full suite against PostgreSQL using disposable per-test schemas, including migration/index and audit-trigger checks.
* **Status vocabulary:** The operational status is `Resolved`, not `fixed`; dashboard “fixed this month” is derived from resolution audit events. This naming is preserved in the API and interface.
* **Auth deviation:** PBKDF2-HMAC-SHA256 at 600,000 iterations is retained for password-hash compatibility rather than migrating to Argon2/bcrypt; refresh tokens remain deferred and login throttling is process-local.
* **Blueprint limitation:** `SecureVision_Master_Blueprint` is absent from this checkout. Section 18 prompts and exact P8-P12 criteria cannot be verified verbatim; `BLUEPRINT_TRACEABILITY.md` and `docs/VIVA_NOTES.md` say so explicitly.
* **Dashboard:** Real total-assets, open-vulnerabilities, critical, and fixed-this-month values are exposed from persisted assets/findings/audit history.
* **Validation (2026-11-12):** Fast suite: 466 passed, 4 PostgreSQL-only tests skipped, 98 warnings. PostgreSQL Compose suite: 470 passed, 98 warnings. Each run's 98 warnings were 96 httpx `app` shortcut deprecations, one `python_multipart` pending deprecation, and one AnyIO `BlockingPortal` deprecation. TypeScript, lint, build, npm audit (0 vulnerabilities), Compose config, and `git diff --check` passed. Isolated HTTP smoke tests and restart persistence passed; Alembic upgrade/check/downgrade lifecycle and synthetic migration checks passed.
* **Known migration gaps:** The application DB role is a PostgreSQL superuser. Only `users.username` has a unique index; asset names and `(asset_id, cve_id)` findings are not unique in the database. `findings.final_priority` is absent as expected for the next phase. The prepared CVE catalog is not packaged or tracked. An existing `backend/.env` prevented a safe clean local setup run; the script refused to overwrite it, and SQLite startup now fails with an actionable message.
* **Next Step:** Resolve the least-privilege and uniqueness gaps before proposal parity; do not promote ML to the deterministic tier without new evidence.
