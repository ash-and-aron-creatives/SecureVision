# Project State: SecureVision
* **Current Phase:** Priority-mode proposal parity implemented; isolated PostgreSQL and Compose verification in progress (2026-11-12).
* **Status:** P5 evaluation remains a negative result. Deterministic 320-rule priority remains the default; `ml_asset` is an opt-in experimental mode with deterministic fallback and a post-model known-exploited floor.
* **Data Split:** Train: 2022-2024, Val: 2025, Test: 2026-01 to 2026-09-08 (Held-Out). Prospective Holdout running daily.
* **Label Definition:** in_cisa_kev_catalog AND (kev_date_added <= published_date + 30 days).
* **Likelihood Provider:** Deterministic scoring remains unchanged. Frozen calibrated XGBoost is an additional advisory signal using publication-time CVSS/vector/CWE/description features only; KEV and EPSS are excluded from model features.
* **ML Risk Formula:** `likelihood × exposure_factor × criticality_factor`; constants, validation-derived risk thresholds, and recommended-action templates are in `backend/rules_config.py`.
* **ML explanations:** `shap==0.46.0` uses `shap.TreeExplainer` on the underlying calibrated XGBoost estimator for the top three factors; failed or unavailable SHAP explanations fall back to native XGBoost `pred_contribs`, then to explicitly unavailable factors.
* **Final priority:** `PRIORITY_MODE` selects `deterministic` or `ml_asset`. Findings persist `final_priority` and `priority_source`; dashboard counts, queue filters/sorting, and CSV/PDF reports use final priority. The drawer shows ML results, the 320-rule cross-check, and when applicable the known-exploited floor.
* **Model Results:** Authenticated `/model/results` and frontend Model Results screen expose only recorded evaluation data, with unavailable metrics left null/not available.
* **Database:** PostgreSQL 16 is the application database. The backend receives only the non-superuser app-role `DATABASE_URL`; only the one-shot `migrate` service receives `MIGRATION_DATABASE_URL` with owner credentials. Pinned driver: `psycopg2-binary==2.9.9`.
* **Schema migration:** Alembic owns the schema, including asset metadata/review fields, ML score-history columns, the CVE cache, audit rows, indexes, PostgreSQL audit immutability triggers, and `findings.final_priority` / `priority_source` with deterministic legacy backfill (revision `0004_final_priority`). Revision `0002_audit_truncate` blocks TRUNCATE; `0003_app_constraints` refuses to migrate duplicate asset names or finding pairs, then enforces case-insensitive asset-name and `(asset_id, cve_id)` uniqueness. App grants are DML-only on application tables, SELECT/INSERT on audit logs, sequence USAGE, and no schema CREATE or DDL rights; owner default privileges preserve future grants. The `migrate` service completes Alembic before the backend starts; backend startup does not run migrations.
* **Authentication:** `/me` is available; login throttling allows five failed attempts per username/IP in 15 minutes and is process-local. Refresh tokens were deferred; PBKDF2-HMAC-SHA256 remains at 600,000 iterations.
* **Assets:** Admin/analyst create, edit, and delete are audited transactionally; assets with findings cannot be deleted. CSV host/IP lookup checks both asset name and `ip_or_domain`.
* **CVE lookup:** The prepared `data/processed/master_cves_2026-10-08.csv` is optional, lazy, and not tracked. Compose can mount a teammate-provided dated file read-only at `/data/cves/<filename>` through `CVE_DATASET_HOST_PATH` and `CVE_DATASET_FILENAME`. Without it, lookup uses PostgreSQL cache/live-provider fallbacks and reports its source or explicit failure; offline scans retain a deterministic tier and mark ML unavailable when description data is missing. Three `DEMO_CACHE` values are illustrative, not authoritative live scores.
* **Deployment:** Compose uses PostgreSQL 16 and a named volume with private, environment-supplied credentials and distinct owner/app roles. No database host port is published by default; `docker-compose.local.yml` adds a loopback-only port for local development. Backend startup waits for PostgreSQL health and successful one-shot migration. `setup_dev.ps1` refuses to overwrite an existing `backend/.env` and runs the migration service before app-role initialization.
* **Synthetic demo:** Compose explicitly enables `SECUREVISION_DEMO_MODE`; the demo seeder uses the same configured `DATABASE_URL` as the app and never clears existing rows. The UI shows a synthetic-data badge in demo mode. Seeded ML predictions are intentionally unavailable without NVD enrichment.
* **SQLite conversion:** `scripts/sqlite_to_postgres.py` is manual-only and source-read-only. It was exercised only with a newly created synthetic source and isolated PostgreSQL targets; it preserved IDs/timestamps, copied score history/audit rows, filled legacy asset metadata, reset sequences, verified counts, and refused a nonempty rerun. It is never called by routine startup.
* **Testing strategy:** All tests require PostgreSQL and the Compose `postgres-tests` profile; fixtures use disposable per-test PostgreSQL schemas, including migration/index, duplicate, concurrency, and audit-trigger checks. SQLite is not a test database.
* **Status vocabulary:** The operational status is `Resolved`, not `fixed`; dashboard “fixed this month” is derived from resolution audit events. This naming is preserved in the API and interface.
* **Auth deviation:** PBKDF2-HMAC-SHA256 at 600,000 iterations is retained for password-hash compatibility rather than migrating to Argon2/bcrypt; refresh tokens remain deferred and login throttling is process-local.
* **Blueprint limitation:** `SecureVision_Master_Blueprint` is absent from this checkout. Section 18 prompts and exact P8-P12 criteria cannot be verified verbatim; `BLUEPRINT_TRACEABILITY.md` and `docs/VIVA_NOTES.md` say so explicitly.
* **Dashboard:** Real total-assets, open-vulnerabilities, critical, and fixed-this-month values are exposed from persisted assets/findings/audit history.
