# SecureVision Blueprint Traceability

| Requirement | Backend implementation | Frontend surface | Automated verification |
|---|---|---|---|
| Deterministic vulnerability scoring | `backend/scoring_engine.py` (`calculate_priority`) evaluates KEV, exposure, criticality, EPSS, and CVSS. | Dashboard and finding detail explain the tier, score, and scoring inputs. | `backend/tests/test_scoring.py::test_scoring_matches_documented_expected_tier_table` checks all 320 rows in `docs/scoring_matrix_v1.csv`; `test_scoring_epss_boundaries` and `test_scoring_cvss_boundaries` check band boundaries. |
| JWT authentication, password hashing, and login audit | `backend/auth.py` hashes passwords with PBKDF2-HMAC-SHA256 using 600,000 iterations and signs JWTs with the configured `SECRET_KEY`; `/token` uses `TokenResponse` and records success/failure audit entries without passwords. Failed usernames receive the same response and an unlinked attempted-username audit record. | `frontend/src/hooks/useLogin.ts`, `frontend/src/api/login.ts`, and `frontend/src/types/index.ts`. | `backend/tests/test_auth.py` covers password hashing, configured signing keys, success/failure auditing, identical failed-login responses for known/unknown usernames, rejected tokens, and configured CORS origins; response-shape assertions are in `backend/tests/test_response_models_and_transactions.py`. |
| Initial administrator setup and password rotation | `init_db.py` creates the `admin` account from `ADMIN_INITIAL_PASSWORD` if it does not exist; `update_admin.py` rotates its password and records an audit event. | The login form accepts the administrator's credentials. | `backend/tests/test_auth.py` covers password hashing and login; the scripts provide the bootstrap and rotation paths. |
| Scanner CSV import and validation | `backend/csv_import.py` detects generic, Nessus, Qualys, and OpenVAS/Greenbone headers; maps host identifiers, expands multi-CVE cells, validates all row errors and flexible dates, and accepts UTF-8 CSVs up to 5 MiB and 5,000 data rows. `backend/main.py` previews the detected format, supports optional review-flagged asset creation, uses file CVSS when available, and commits findings/assets/audit data atomically. | `frontend/src/components/import/ImportView.tsx` shows the detected format, row results, optional missing-asset creation, and disables commit when no rows are valid. | `backend/tests/test_csv_import.py` covers adapters, CVE splitting, multi-error rows, BOM/quoted fields, date formats, formula injection, duplicates, and file limits; `backend/tests/test_response_models_and_transactions.py::test_csv_import_creates_missing_asset_with_review_flag_and_file_cvss` checks auto-creation and file CVSS. Samples are in `sample_data/`. |
| Finding queue and triage | `backend/main.py` provides paginated, filtered findings, finding details, and status updates. Search includes explanation summaries. | `frontend/src/api/dashboard.ts` loads pages of 100 up to a 10,000-finding safety cap; dashboard analytics come from the backend, while queue search and tier filtering cover the loaded findings and report export uses matching filters. | `backend/tests/test_findings_api.py::test_findings_over_twenty_are_reachable_across_pages` verifies all 26 findings can be retrieved over multiple pages; other findings API tests cover filters and details. |
| CVE intelligence availability and validated scan scoring | `backend/main.py` validates CVE identifiers on `/intel/{cve_id}` and `/scan` with 422 responses; `IntelResponse` keeps EPSS/CVSS nullable. `backend/threat_intel.py` preserves explicit provider errors. `/scan` rejects unresolved scores with 503; CSV import skips rows without complete intelligence. | `frontend/src/api/intel.ts` and `frontend/src/hooks/useScan.ts` surface lookup errors and only populate available scores; Scan is rendered by `frontend/src/components/scan/ScanView.tsx`. | `backend/tests/test_threat_intel.py`, `backend/tests/test_scan_assets_audit.py`, `backend/tests/test_response_models_and_transactions.py`, and `backend/tests/test_role_based_api.py` cover provider failures, 422 validation, scan rejection, response shape, and skipped imports. |
| Repeated scan updates and reopens | `backend/main.py` reports whether an existing scan reopened a resolved finding. | `frontend/src/hooks/useScan.ts` replaces the action banner with “Finding updated: …” and adds “(reopened)” when applicable. | `backend/tests/test_scan_assets_audit.py::test_repeated_scan_updates_existing_finding_and_reopens_resolved` asserts the reopen signal and persisted Open state. |
| Findings and executive reports | `backend/reports.py` provides authenticated, filtered CSV and executive PDF downloads and records each export's format, filters, row count, and SHA-256 digest. | `frontend/src/api/client.ts` downloads authenticated report blobs using server-provided filenames; queue export forwards the active tier and search filters and errors are shown in the action banner. | `backend/tests/test_reports.py` verifies report content, filters, authentication, and export audit entries. |
| Role-based user management | `backend/users.py` supports user creation, role changes, password resets, and deletion, audits successful mutations, and blocks self-removal and removal/demotion of the last administrator. | Admin-only Users tab in `frontend/src/components/users/UsersView.tsx` provides role, password-reset, and delete controls with delete confirmation and account-protection messaging. | `backend/tests/test_users_rbac.py` and `backend/tests/test_role_based_api.py` cover role permissions, last-admin/self protections, and audit entries for successful mutations. |
| Audit trail | `backend/models.py` and `backend/database.py` enforce audit-record immutability for SQLite; login success/failure, exports, and administrative actions are recorded by the backend. | Admin-only Audit tab in `SecureApp.tsx`. | `backend/tests/test_auth.py`, `backend/tests/test_reports.py`, `backend/tests/test_users_rbac.py`, and `backend/tests/test_scan_assets_audit.py`. |
| ML-assisted prioritization (advisory only) | `backend/ml_inference.py` lazily loads only the frozen configured XGBoost model from `ml/models`, uses publication-time NVD description/CVSS/vector/CWE features, and persists nullable likelihood/risk/priority/factors/version in `FindingScore` history. `backend/rules_config.py` owns exposure/criticality factors, validation-derived P99/P90/P50 risk thresholds, and action templates. ML is not passed to `calculate_priority`; the 320-rule tier remains byte-identical. | Finding drawer separates the deterministic tier from “ML-assisted risk (experimental, advisory)” and shows the negative offline result. Model Results is visible to every role and reads recorded `docs/results/` files without changing them. | `backend/tests/test_ml_advisory.py` verifies unavailable paths, mocked predictions, deterministic-tier invariance, factor/threshold mapping, KEV/EPSS feature exclusion, existing-database migration, and `/model/results` authentication/schema. The negative evaluation is recorded in `docs/results/p5/p5_console.log`; decision and thresholds are in `Decision_Log.md`. |
| Seeded demonstration data | `seed_db.py` populates the configured database with demonstration data. | Findings and assets appear in the application after sign-in. | Seed data is provided by the script; this is not represented as an automated pytest assertion. |
